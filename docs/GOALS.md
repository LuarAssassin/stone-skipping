# 游戏目标与体验原则

记录日期：2026-11-14。来源：本线程关于打水漂游戏的讨论；其中核心目标明确于 2026-11-14 05:33:05 America/Los_Angeles，目录与规划请求发送于 05:36:26。记录日期不是开发完成日期。

## 1. 一句话目标

在一处有漂亮风景、固定大小湖面的岸边，投出石子，体验可信的飞行、擦水、飞溅、波纹和连续弹跳，并通过技巧与石头选择不断取得更好的成绩。

核心不是展示通用水体模拟，也不是以商店和升级驱动的数值小游戏，而是把真实打水漂的感受做得优雅、清晰、令人愿意反复体验。

## 2. 用户已明确的方向

### 真实投掷是最高优先级

- 弧线、跳跃高度、速度衰减和最终沉水要自然。
- 水花、波纹等反馈要细致、逼真，能体现具体的入水状态。
- 认真考虑投掷角度、力度、入水速度及角度、风和水体状态。
- 相同外部条件下，石头自身属性应产生可解释的表现差异。
- 风景是体验的一部分，但不挤占核心运动与水体反馈的研发优先级。

### 石头选择与成长

- 玩家可以选择石头。
- 弹跳次数累积为可兑换的积分，逐步解锁更好的石头。
- 石头具有不同面板属性，且面板影响实际运动。
- 具体兑换价格、解锁顺序、积分结算公式尚未确定，在成长阶段设计。

### 平台顺序

- 先网页版；网页表现满足目标时，仅网页即可。
- 有明确需求时再做桌面客户端，之后考虑 iOS。
- GPUI 曾作为原生壳候选讨论；目前未决定采用，不先为它建立工程。

## 3. 本轮实现建议

以下是为了落实目标提出的设计建议，不把它们记录为用户已逐项确认的规格。

### 一次接触，一组一致的反馈

石子与水的同一次接触过程应提供接触点、相对速度、姿态、接触时长、冲量及能量变化，驱动：

1. 石子的后续运动。
2. 水面扰动与扩散波纹。
3. 有方向性的飞溅、细小水滴和短暂泡沫。
4. 触水声音与远近衰减。

视觉可以采用近似，运动也可以采用经校准的简化模型，但不把预设弹跳序列当成真实运动，不让水花大小与入水强弱脱节。

### 分清四种容易混淆的角度与旋转

- 出手仰角：初始速度相对水面切平面的方向。
- 石面倾角：石头平面相对局部水面的姿态。
- 入水角：触水时相对速度指向水面的角度；它是飞行结果，不等于出手仰角。
- 自旋与翻滚：分别影响姿态稳定和接触过程，不能只用视觉旋转代替。

玩家操作最终要自然；这些独立变量先在开发实验界面中表达，等运动规律清楚后再映射为鼠标、触屏手势。

### 石头面板对应物理参数

| 面板维度 | 底层建议表示 | 可观察的差异 |
|---|---|---|
| 重量 | 质量，结合体积与密度保持自洽 | 同样冲量下速度不同；同样出手速度下动量不同 |
| 大小与扁平程度 | 长短轴、厚度、接触面积函数 | 入水接触形态与流体受力差异 |
| 形状 | 轮廓、边缘、近似碰撞/浸水几何 | 触水阻力、偏转与接触位置差异 |
| 旋转稳定性 | 惯性张量、初始角动量、受力矩 | 姿态保持和失稳方式 |
| 熟练度辅助显示 | 由测试投掷统计得到的容错区间 | 帮助理解，不直接加固定跳数 |

“更好的石头”可在常用投掷条件内有更好的续跳和容错表现。它不必在每一种速度、姿态和风况下都占优；这种差异让选择有意义。

测试时要明确比较条件：“相同出手速度”和“相同施加冲量”是不同实验，不把质量变化后的结果混在一起。

### 让技巧仍然有价值

建议初始石头就能成功连续弹跳。解锁扩大可发挥的范围与稳定性，而不是把好手感锁在后期。第一版不加入飞行中再次点击强行加力的操作，优先保留出手之后自然演化的体验。

## 4. 第一段可玩的体验

- 一个固定投掷点，一块可配置的扁石，一小片有边界的湖水。
- 能调整方向、力度、石面姿态和自旋，完成投掷、弹跳、失稳及沉水。
- 每次触水有同步的水花、波纹和声音。
- 能重新投掷，显示本次跳数与距离。
- 一处有初步构图与光照的岸景；不先堆大地图和大量资产。
- 开发模式可以慢放、暂停、单步、重放并查看受力，普通游玩界面保持简洁。

这是一项体验目标，不是已经实现的功能清单。

## 5. 质量判断

- **可信**：轨迹来自运动计算，改变参数能观察到有解释的变化。
- **一致**：石子、水面、水花和声音对同一接触给出一致反馈。
- **可学习**：玩家能感知倾角、力度和旋转的影响，重复练习有收益。
- **可感知**：远处弹跳仍看得清，不靠夸张的不自然轨迹保持可见。
- **优雅**：界面、镜头和声音不打断投掷；不以满屏数字遮住水面。

科学数据用于校准运动；游玩测试用于判断操作与感受。两者各自记录，不用“看起来不错”替代物理比较。

## 6. 当前不投入的内容

先不做完整商店、复杂任务、联网排名、多湖区、大型引擎框架、完整三维湖水求解、桌面套壳与 iOS 工程。它们不是被否定，而是排在核心投掷体验之后。具体顺序见 [实现计划](IMPLEMENTATION_PLAN.md)。
