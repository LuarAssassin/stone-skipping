# 湖面手势：第三步实现与验证

## 玩家操作

- 在湖面用鼠标左键或单指按住；横拖调整方向，上拖提高出手仰角、下拖压低；松开投掷。建议第一次按约0.7秒，轻拖或不拖，石面保持6°。
- 小于120ms的松手是误触，不出手。超过120ms可原地按住出手，不要求额外拖动距离；1.4秒达到最大蓄力，继续按住不会循环或自动出手。
- 蓄力条、速度、方向角、仰角、石面倾角实时显示。箭头是目标方向的抽象指示，不是摄像机投影后的物理轨迹，也不预测跳数。轨迹辅助继续默认关闭。
- 石面倾角使用常驻的精简滑块；自旋留在开发详情，默认18转/s。不把所有姿态塞进一次手势。
- Esc、第二触点、pointercancel、捕获丢失、窗口失焦、页面隐藏和窗口尺寸变化都会清除蓄力，不创建投掷。拖动时正在飞行的石子继续原模拟，不因预览而暂停或改变。
- 右侧/底部保留按钮投掷、暂停、重放、单步。开发详情中保留五项原目标滑块、温度T0..2、慢放、跟随、轨迹、JSON和诊断。T1默认不变，T0仍是无扰动实验。

## 精确映射与近似

`gesture.ts`不依赖DOM、Three运行时、随机数或渲染时钟；只接收位置、指针ID、时间和起始目标值。

按下时冻结画布矩形和目标副本。坐标为 `x=clamp((clientX-left)/width,0,1)`、`y=clamp((clientY-top)/height,0,1)`，是实际可用画布区域而不是整个窗口；捕获后拖出边界按边缘截断。DOMRect的属性来自原型，必须显式复制left/top/width/height，不能对象展开。

- `direction=clamp(base.direction+70*(x-x0),-35,35)` 度。横向拖动画布宽度的四分之一，目标改变17.5°。
- `elevation=clamp(base.elevation-24*(y-y0),-8,14)` 度。上拖画布高度六分之一，目标提高4°。
- `duration=max(0,eventTime-startTime)` 毫秒；`power=clamp((duration-100)/1300,0,1)`；`speed=8+6*power` m/s。
- 700ms对应约10.77m/s；1400ms对应14m/s。短有效按住不是最大力度，力度只依赖持续时间，不依赖move次数。
- 石面倾角和自旋取按下时的目标副本；不使用压力或释放速度，因此没有依赖浏览器事件频率的速度差分/平滑近似。
- 手势结束后的目标同步到开发滑块。下一次手势在这些目标基础上相对调整方向和仰角，但速度总由本次持续时间重新生成；开发速度滑块仍作用于按钮投掷。

一般PointerEvent使用原始timeStamp，RAF的同源单调时间只驱动显示。Linux Alma/WebKit侧栏的输入桥接会给原生指针事件timeStamp=0；仅对非正时间戳，输入适配器使用performance.now()回退。纯状态机不猜浏览器频率。真实Chrome CDP验证提供事件时间戳，证实有效release按事件时间而非执行延迟计算；繁忙的无效时间戳桥接环境只能按实际接收时间近似，不能声称等同硬件采集时刻。

## 状态与快照边界

- Idle → begin → Active（冻结矩形、目标、指针、起点与时间）。Active拒绝其他指针抢占；页面输入层遇到第二触点取消整个手势。
- move只更新匹配指针的位置。preview每次返回新对象，不修改目标副本、模拟或快照。
- release只接受所属指针、更新最终位置并消费Active；不足120ms返回空。重复release、取消后的release都不会出手。
- 有效release调用已有`start(false,target)`：抽取新seed，按释放时当前温度调用sampleThrow，保存target与sampled，再复用原Simulation/Clock、效果池、trail、visualTime与accumulator重置路径。
- 原快照重放仍只消费旧sampled；拖动/取消不会改变正在飞行的Simulation、已有target/sample或JSON。按钮新投、重放、载入快照也先取消未完成手势。
- 固定物理步采样、effects时钟、沉水后继续推进效果时钟与末段消散代码保持原路径，没有改physics/effects/sheets/water实现。

## 布局

桌面画布独占窗口左侧，右侧300px为面板，底部32px为状态；1024×768下实际画布724×736。移动宽度≤700px时底部面板218px、状态28px，390×844下画布约390×598。提示覆盖画布底部但pointer-events:none，不挡投掷。开发详情在固定高度底部面板内部展开滚动，不扩张占满湖面。touch-action:none仅施加canvas，面板保留原生滚动。

## 浏览器实际验证

未调用业务start充当输入。侧栏使用locator/坐标点击、Input.dispatchMouseEvent、真实按住等待、移动与释放；读取页面快照/计分仅用于断言。

- 1024×768桌面截图已查看，开发参数初始收起，画布可操作。一次短蓄力拖动目标10.262m/s，T1样本打出6跳/7.6米；长按目标14m/s，另一seed为7跳/13.3米，不预设成绩。
- Esc取消后松开没有新快照、蓄力归零；点击面板倾角/开发控件不会湖面出手。原快照在后续控件操作后重放仍为7跳/13.3米/2.16s，JSON保持一致。
- 温度滑块用实际鼠标点击到0，再点投出，确认temperature=0且target严格等于sampled；最后重载恢复默认T1。
- 侧栏390×844截图已查看，底部紧凑控制与可用湖面正常；但该Linux/WebKit侧栏把CDP touch命令转换成pointerType=mouse，并把touchCancel转换成pointerup，不能把它冒充真正的触屏取消验证。
- 因此补用独立临时Chrome + 原生CDP触屏仿真：确认pointerType=touch；390×844下按住、移动、释放创建新快照。一次明确700ms事件序列目标约10.769m/s，实际6跳/8.7米；另一次实时输入7跳/11.9米，均由模拟决定。
- 真正touchCancel、第二触点、20ms误触、尺寸变化、已建立捕获后的releasePointerCapture、Esc均不创建新快照且蓄力清空。展开详情后真实点击JSON文本框不出手，面板内部scrollTop=728而湖面高度不变。
- Headless Chrome切换目标窗口不实际产生OS blur；失焦监听路径以真实触屏按下后派发window blur事件做集成验证，不冒充真实操作系统窗口切换测试。
- 桌面和真正触屏截图均已自行查看。最终侧栏恢复1024×768、初始暂停、0跳、T1、开发收起，可直接操作，不遗留mobile尺寸。
