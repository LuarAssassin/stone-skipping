# 实现顺序与检查点

规划日期：2026-11-14。

本轮交付是目录、研究记录与实施规划，不启动游戏开发。下列是拟定顺序；文档落地不等于对应功能已实现。

## 1. 总体顺序

**石子飞行与姿态 → 入水受力与连续弹跳 → 同源水花/波纹/声音 → 自然投掷操作与漂亮湖岸 → 不同石头与积分解锁 → 性能与发布。**

不从商店、通用引擎或整湖体积流体开始。先建一个有诊断能力的小型实验场，再把它打磨成真实、优雅的投掷体验。

| 阶段 | 交付 | 状态 | 依赖 |
|---|---|---|---|
| M0 | 目标、研究索引、实施顺序 | 已完成本轮文档整理 | 本线程讨论 |
| M1 | 可复现的石子飞行与姿态实验场 | 未开始 | M0 |
| M2 | 可信的接触、续跳、失稳与沉水 | 未开始 | M1 |
| M3 | 水花、波纹、声音与接触联动 | 未开始 | M2 的接触输出格式 |
| M4 | 完整投掷手感与一处优雅湖岸 | 未开始 | M2、M3 |
| M5 | 不同石头、积分与解锁 | 未开始 | M4 核心体验通过试玩 |
| M6 | 目标设备优化、网页交付与移动适配 | 未开始 | M4 可测，M5 可并入最终包 |

性能采样从 M1 开始，不等 M6 才测；基础构图和光照从实验场就保留，M4 才投入完整景观。每阶段优先产出可观察结果，不为不相干边界扩展工程。

## 2. M1：石子飞行与姿态实验场

### 先解决的问题

投掷速度、石面姿态和自旋如何共同决定接近水面的状态？需要什么模型才能得到可解释的运动？

### 工作内容

1. 补齐必要的一手物理资料，检查一份公开专项实现的方程与许可证。先选一套能落地的模型，不穷举全部论文。
2. 创建 TypeScript + Vite + Three.js 最小工程，选定实际可用的渲染后端并记录版本。
3. 建立有限水面、岸边参照、扁石和基本光照，用米、秒、千克表示物理量。
4. 物理模块独立于渲染：质量、几何、惯性、位置、线速度、四元数姿态与角动量；固定时间步和渲染插值。
5. 提供开发界面：初始位置、方向/仰角、速度、石面倾角、自旋与风；暂停、单步、慢放、重置和轨迹显示。
6. 记录初始条件、种子、物理步数和版本，支持同一输入的重放；采集物理/渲染 CPU 耗时，条件允许时采集 GPU 耗时。

### 可验证结果

- 无水接触、无空气阻力时，运动与解析抛体基线吻合；测试中写出单位与所用误差标准。
- 旋转更新保持姿态有效，自旋不是只转模型外观。
- 同一运行环境下，相同初始条件重放能复现轨迹；改变显示帧率不会改变投掷结果。
- 暂停、慢放和开发 UI 不额外给石头施力。
- 能导出一份参数与轨迹记录，作为后续接触模型的固定对照。

**阶段产物：**可运行实验页、物理基线测试、模型/单位说明、首份设备与浏览器采样记录。

## 3. M2：可信的触水与弹跳

### 工作内容

1. 先在静水与零风下校准；接触用局部水面法线与石子几何，不只判断质心穿过一个平面。
2. 实现有限时长的入水接触与流体作用力/力矩积分；可同时保留简化冲量模型作调试对照，最终按资料与观察选择。
3. 高速接触采用扫掠检测或局部子步，保证擦水过程不会被时间步跨过。
4. 弹起、离水、再次入水、失稳和沉水由运动状态决定；不预先指定跳数或下一段弧线。
5. 加入能量、动量与受力诊断。静水无外部供能时检查没有持续无来源的能量增益；风或动态水面做功单独记录。
6. 输出可被视觉/声音消费的接触数据：时间、位置、法线、相对速度、接触阶段、交换冲量、能量变化与接触面积估计。
7. 统一“有效一跳”的判定：一次独立触水后再次离开水面，计作一次成功弹跳；同一次接触内部的多个子步不重复计数，最终入水不计作成功弹跳。

### 对照实验

| 输入变化 | 检查内容 |
|---|---|
| 固定石头，改变出手速度 | 跳数、距离、触水过程如何变化，能否用受力解释 |
| 固定速度，改变石面倾角 | 成功擦水与失败入水的区别，不靠预设动画区分 |
| 固定其他输入，改变自旋 | 姿态保持、力矩响应与失稳变化 |
| 减小物理时间步 | 轨迹、接触次数与能量诊断是否趋于稳定 |
| 相同速度比较不同质量/形状 | 明确固定的实验条件，解释差异 |
| 微小扰动初始条件 | 检查是否存在非物理的跳数突变或碰撞穿透 |

### 可验证结果

- 一块石头能自然经历多次续跳和最终沉水，也能在不合适输入下首次触水就失败。
- 轨迹不是固定时长、固定高度的弹跳模板；后续弧线由接触后的状态产生。
- 物理记录能够解释每次弹跳的速度、姿态和能量变化；找到可复现的错误输入，而不是只录成功演示。
- 用文献/实验或可读参考实现建立至少一个校准场景，明确资料适用条件与简化项。

**阶段产物：**石子—水面接触模块、固定输入测试集、慢放诊断演示与模型决策记录。

## 4. M3：水花、波纹与声音闭环

### 工作内容

1. 以 M2 的同一接触记录为输入，接通水面高度场扰动、局部飞溅粒子和空间音效。
2. 水花方向随入水方向/姿态变化，强度与接触交换量相关；避免每次播放完全相同的水花。
3. 基础水面、局部波纹与近景水花分层实现；先做可信的弹道飞溅，再按近景差距决定是否加入更强局部流体求解。
4. 水面渲染逐步加入反射、折射、深度吸收与接触处细节。焦散、泡沫等按实际画面收益加入，不要求一次集齐。
5. 处理连续触水的时间与空间对应；每次撞击只触发一次有效的声音/粒子事件，持续接触量单独更新。
6. 设计 CPU 与 GPU 数据流，避免每个物理子步同步回读整张水面；基础波面参数与物理采样保持一致。
7. 为每次接触记录水花、波纹、声音输入，便于重放与调参；粒子随机数使用可记录种子。

### 可验证结果

- 慢放时，石子接触点、水花起点、波纹起点重合；声音按事件时间与距离调度。
- 不同入水强度、角度和速度具有可辨别的视觉与听觉差异。
- 连续多次触水后，粒子数和资源占用回落，不随重投无限增长。
- 记录水面/水花/场景分项开销，知道主要成本在哪里。

**阶段产物：**“一种石头 + 一片水”的完整投掷闭环、近景触水慢放、反馈参数与性能记录。

**第一个核心试玩检查点：**反复投掷是否已经有真实、值得练习的感觉？先在这里调好物理与反馈，再进入内容扩充。

## 5. M4：自然操作、镜头与优雅湖岸

### 工作内容

1. 将实验参数映射到正常操作：瞄准、蓄力、出手倾角与自旋。先提供鼠标操作，同时设计可对应的触屏手势。
2. 给出清晰而轻量的出手反馈，不把调试滑块直接当作游戏 UI。
3. 比较固定岸边视角与轻微跟随/观察辅助，让远处弹跳看得清，同时保留投掷的空间感。
4. 用 Blender 制作首块正式石头与一组近岸资产，统一尺度、轴向、原点、碰撞近似与 PBR 贴图，完成 GLB 导出/导入。
5. 构建一处有限湖面的景观：近处石滩、草/芦苇，中远景山林/天空，配合反射、雾和有层次的光照。
6. 加入克制的风声、鸟鸣、界面与成绩展示；提供重投、暂停和音量控制。
7. 用普通速度观察整体手感，用近景慢放观察真实感；分别记录改动，不为镜头遮掩修改物理轨迹。

### 可验证结果

- 玩家不操作开发面板也能完成第一次投掷，并理解如何改变下一次表现。
- 一颗石头的投掷、连续弹跳、落水、结算和重投形成完整循环。
- 岸景、反射与声音增强投掷体验，不遮挡石头和触水反馈。
- GLB 尺度与物理几何一致，正式构建可加载资产，不依赖本机绝对路径。

**阶段产物：**可交给用户试玩的湖岸垂直切片，以及第一轮实际反馈记录。

## 6. M5：石头差异与积分解锁

### 工作内容

1. 建立少量有清晰差别的石头定义，质量、几何和惯性对应真实计算；面板值从同一配置读取。
2. 用 M2 固定投掷集比较石头，在常用条件范围定义“更好”的续跳和容错表现。
3. 实现本次跳数/距离、累计弹跳积分、兑换与石头选择；明确结算时机，重放与调试不重复发分。
4. 初始石头保留可练习的连续弹跳能力；解锁通过物理属性改善表现，不直接改最终跳数。
5. 用最小本地存档保存已解锁石头、积分和个人纪录。

### 可验证结果

- 同一初始条件下更换石头，差异能追溯到物理参数，而非随机隐藏奖励。
- 面板、模型和物理定义一致；购买、选择、重开页面后状态正确。
- 积分结算可复现，不能在查看重放时反复领取。

**阶段产物：**石头配置与比较记录、最小解锁循环、本地存档及对应测试。

## 7. M6：性能、移动与网页交付

### 工作内容

1. 以实际设备、浏览器、分辨率和同一投掷场景建立性能记录：帧耗时分布、物理 CPU、GPU（可测时）、资源数量、加载耗时。
2. 优先优化测到的瓶颈：水面分辨率、粒子数量、反射更新、阴影、像素比、绘制调用与资源生命周期。
3. 视觉质量分档不改变石子的核心物理结果；自动/手动档位使用同一物理回放做比较。
4. 验证触屏操作、横屏布局、音频解锁与浏览器前后台切换；运行中断采用清晰暂停/恢复策略。
5. 运行正式构建，检查资源路径、缓存、加载提示与本地存档，产出可部署静态网页。
6. 如需要安装入口，再加入 PWA；桌面客户端与 iOS 原生包装分别评估，不仅为了“有多端”就立项。

### 可验证结果

- 同一固定投掷在目标设备上有记录，性能目标以实际画质与设备决策确定，不借用上游 Demo 的粒子规模当承诺。
- 正式包可独立部署，离开本工作区仍可加载模型、贴图与声音。
- 连续多轮投掷后资源稳定；画质分档不改变计分与物理轨迹。

**阶段产物：**可部署网页版、使用说明、已测设备与画质记录。网页满足体验时，就在网页交付，不必迁移桌面。

## 8. 建议的代码边界

实际目录在 M1 创建，不提前生成空文件树。

- `physics/`：石头状态、空气/水体作用、积分、接触与诊断；不依赖 Three.js 场景对象。
- `water/`：基础波面采样、GPU 波纹、水花与材质；消费接触输出。
- `game/`：投掷流程、输入、计分、石头配置与解锁。
- `scene/`：相机、环境、资产、光照。
- `audio/`：接触与环境音。
- `debug/`：参数、重放、轨迹和性能观察。

这是项目内部职责划分，不另建一套通用引擎、插件系统或多端抽象。

## 9. 动手时的第一张任务单

1. 读取目标文档与专项研究，选定第一版石头几何和单位。
2. 核对一份打水漂物理原始资料与一份专项代码，写下将采用的方程及适用条件。
3. 创建最小网页工程和可复现的无接触飞行实验。
4. 把石面姿态、自旋和轨迹显示接上，保存第一个基线输入。
5. 加入最小水面接触，得到第一条自然产生的弹跳轨迹。

做到第五项就有首个可看的运动结果；再沿 M2/M3 细化，不等全部论文、景观、平台和成长设计完成才开始运行。
